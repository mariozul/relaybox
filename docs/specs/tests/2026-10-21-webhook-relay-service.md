Idiomatic Go Test Patterns & Flakiness Prevention\n- All tests will use `t.Run()` for table-driven scenarios.\n- Time-sensitive logic will inject `time.Time` or a clock interface.\n- Integration tests will use `t.Cleanup()` for resource teardown.\n- Concurrency tests (`-race` flag) will use `sync.WaitGroup` or channels, avoiding `time.Sleep`.\n- Minimum 85% statement coverage on domain/service logic, 100% branch coverage on error handling.
