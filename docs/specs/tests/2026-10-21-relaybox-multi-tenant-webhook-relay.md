# TestSpec: Relaybox — Multi-Tenant Webhook Relay Service\n\n## Document ID: relaybox-trd\n\n### 1. Test Case Taxonomy\n- `TC-xx-UNIT`: Isolated unit test (mocked external I/O, pure domain logic).\n- `TC-xx-INT`: Integration test (live database transactions, HTTP transport, cache adapter).\n- `TC-xx-RACE`: Concurrency race test (multi-goroutine / parallel requests).\n- `TC-xx-EDGE`: Boundary and error handling test (overflow, zero values, timeouts, network partitions).\n\n### 2. Traceability Matrix & Test Scenarios\n\n| Test ID | Test Scenario | Mapping (FR & AC) | Category | Violation Signal |\n| :--- | :--- | :--- | :--- | :--- |\n| `TC-ING-01-INT` | Successful event ingestion via POST /v1/events | `FR-ING-01` | Integration | The event is not persisted in the database or the HTTP handler returns a non-200 status for a valid request. |\n| `TC-ING-02-EDGE` | Event ingestion fails when tenant_id is missing from context | `FR-ING-01`, `RULE-SEC-01` | Edge | The handler accepts the request without a valid tenant_id in the context or does not return a 403/401 error. |\n| `TC-ING-03-INT` | Event persistence and outbox enqueue are atomic (transactional) | `FR-ING-02`, `RULE-DATA-01` | Integration | If event persistence succeeds but outbox enqueue fails, the Integration | After an event is persisted and the service is restarted, the event is never processed by the dispatcher, or the outbox entry is lost. |\n| `TC-ING-05-INT` | Duplicate event ingestion
