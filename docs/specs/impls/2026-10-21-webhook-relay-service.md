# ImplSpec: Relaybox — Multi-Tenant Webhook Relay Service (YYYY-MM-DD-relaybox.md)\n\nThis document outlines the implementation plan for the Relaybox service, adhering to Clean Architecture principles and without writing full implementation logic.\n\n## 1. Core Principle: Contracts, Not Implementation\nThis specification defines struct definitions, interface method signatures, sentinel error constants, and godoc documentation only. Full function implementation bodies or complete algorithms are explicitly omitted, as they are the responsibility of the Coding Agent.\n\n## 2. Clean Architecture 7-Layer Component Mapping\n\n### ST-01: Core Domain Entities and Errors\n- **Layer**: Entity, Domain Service\n- **Components**:\n    - `pkg/domain/event.go`: `Event` struct, `EventStatus` enum, factory methods, validation.\n    - `pkg/domain/subscription.go`: `Subscription` struct, `TargetURL` value object, factory methods, validation.\n    - `pkg/domain/delivery.go`: `DeliveryAttempt` struct, `DeliveryStatus` enum.\n    - `pkg/domain/errors.go`: Sentinel errors (`ErrNotFound`, `ErrConflict`, `ErrInvalidInput`, `ErrPermanentDeliveryFailure`).\n\n### ST-02: Database Schema and Migration\n- **Layer**: Adapter (Infrastructure)\n- **Components**:\n    - `migrations/YYYYMMDDHHMMSS_create_tables.up.sql`: SQL script to create `events`, `outbox`, and `subscriptions` tables.\n        - `events`: `id (PK)`, `tenant_id`, `event_type`, `payload (JSONB)`, `dedup_key (UNIQUE ON tenant_id, dedup_key)`, `status`, `created_at`, `created_by`, `updated_at`, `updated_by`.\n        - `subscriptions`: `id (PK)`, `tenant_id`, `event_type`, `target_url`, `created_at`, `created_by`, `updated_at`, `updated_by`.\n        - `outbox`: `id (PK)`, `event_id (FK to events.id)`, `subscription_id (FK to subscriptions.id)`, `status`, `attempts`, `next_attempt_at`, `last_attempt_at`, `error_message`, `created_at`.\n    - `migrations/YYYYMMDDHHMMSS_create_tables.down.sql`: SQL script to drop these tables.\n\n### ST-03: Repository Interfaces and In-Memory Implementations\n- **Layer**: Repository (Interface), Adapter (In-Memory Implementation for testing)\n- **Components**:\n    - `pkg/repository/event.go`: `EventRepository` interface (`SaveEvent`, `GetEventByDedupKey`).\n    - `pkg/repository/subscription.go`: `SubscriptionRepository` interface (`SaveSubscription`, `GetSubscription`, `ListSubscriptions`, `UpdateSubscription`, `DeleteSubscription`).\n    - `pkg/repository/outbox.go`: `OutboxRepository` interface (`Enqueue`, `GetPending`, `UpdateStatus`).\n    - `pkg/repository/inmem_event_repo.go`, `pkg/repository/inmem_subscription_repo.go`, `pkg/repository/inmem_outbox_repo.go`: Simple in-memory implementations for testing.\n\n### ST-04: PostgreSQL Repository Implementations\n- **Layer**: Adapter (Infrastructure)\n- **Components**:\n    - `pkg/infrastructure/postgres_event_repo.go`: `PostgresEventRepository` implementing `EventRepository`. Methods for `SaveEvent` (with idempotency using `ON CONFLICT DO UPDATE`), `GetEventByDedupKey`.\n    - `pkg/infrastructure/postgres_subscription_repo.go`: `PostgresSubscriptionRepository` implementing `SubscriptionRepository`. Methods for CRUD operations.\n    - `pkg/infrastructure/postgres_outbox_repo.go`: `PostgresOutboxRepository` implementing `OutboxRepository`. Methods for `Enqueue`, `GetPending` (with pessimistic lock to avoid race conditions for workers), `UpdateStatus`. Transactional handling for `SaveEvent` + `Enqueue` (RULE-DATA-01).\n\n### ST-05: Event Ingestion Service and HTTP Handler\n- **Layer**: Service (Application), Transport/Handler\n- **Components**:\n    - `pkg/service/ingestion.go`: `IngestionService` struct with `ProcessEvent` method. Depends on `EventRepository` and `OutboxRepository`. Handles `FR-ING-02`, `FR-ING-03`.\n    - `pkg/handler/ingestion.go`: `IngestionHandler` struct with `HandleIngestEvent` method (HTTP `POST /v1/events`). Depends on `IngestionService`. Handles DTO mapping and tenant context extraction (FR-ING-01, RULE-SEC-01).\n    - `pkg/handler/ingestion_dto.go`: Request/response DTOs for ingestion.\n\n### ST-06: Subscription Management Service and HTTP Handlers\n- **Layer**: Service (Application), Transport/Handler\n- **Components**:\n    - `pkg/service/subscription.go`: `SubscriptionService` struct with CRUD methods (`Create`, `Get`, `Update`, `Delete`). Depends on `SubscriptionRepository`. Handles `FR-SUB-01`.\n    - `pkg/handler/subscription.go`: `SubscriptionHandler` struct with `HandleCreateSubscription`, `HandleGetSubscription`, etc. (HTTP `CRUD /v1/subscriptions`). Depends on `SubscriptionService`. Enforces tenant isolation (FR-SUB-02, RULE-SEC-01).\n    - `pkg/handler/subscription_dto.go`: Request/response DTOs for subscriptions.\n\n### ST-07: Event Delivery Service and Bounded Worker Pool\n- **Layer**: Service (Application), Adapter (External HTTP), Cross-Cutting\n- **Components**:\n    - `pkg/delivery/service.go`: `DeliveryService` struct with `DispatchEvents` method. Coordinates `OutboxRepository` and `HTTPClient`. Handles retry logic, exponential backoff, dead-lettering (FR-DEL-02).\n    - `pkg/delivery/worker_pool.go`: `WorkerPool` implementation for bounded concurrency of delivery attempts (FR-DEL-03, RULE-RES-02). Uses `context.Context` for graceful shutdown.\n    - `pkg/delivery/http_client.go`: `HTTPClient` wrapper with OpenTelemetry tracing propagation (FR-DEL-01, RULE-OBS-02), timeouts, and `X-Relaybox-Delivery-Id` header (FR-DEL-04, RULE-DATA-02). Ensures `defer resp.Body.Close()` (RULE-RES-03).\n\n### ST-08: Health Checks and Production Observability\n- **Layer**: Cross-Cutting, Transport/Handler\n- **Components**:\n    - `pkg/handler/health.go`: `HealthHandler` struct with `HandleLivez` and `HandleReadyz` methods (HTTP `/livez`, `/readyz`). `HandleReadyz` checks DB connectivity (FR-OBS-01, RULE-OBS-04).\n    - `pkg/observability/metrics.go`: Prometheus metrics registry setup. Defines `http_request_duration_seconds` histogram, `webhook_delivery_total` counter with `status="delivered|failed|deadletter"` labels (FR-OBS-02, RULE-OBS-03).\n    - `pkg/observability/logger.go`: Structured logger (e.g., `slog`) initialization. Functions for context-bound logging (`slog.InfoContext`, `slog.ErrorContext`) with `trace_id`, `span_id` (FR-OBS-02, RULE-OBS-01).\n\n### ST-09: Main Application Entry Point and Dependency Wiring\n- **Layer**: Config (Main Application)\n- **Components**:\n    - `cmd/relaybox/main.go`: Main function. Initializes configuration, database connection, repositories, services, handlers, HTTP server, and graceful shutdown (via `context.WithCancel` and `os.Interrupt` signals).\n    - `go.mod`, `go.sum`: Dependency management files for Go modules.\n\n## 3. Database Performance & Query Optimization (Implicit)\n- Repositories must avoid N+1 query patterns (RULE-DATA-03). Batch lookups and JOINs are preferred.\n- Queries will utilize appropriate indexing for `tenant_id`, `dedup_key`, `event_type`, `status`, `next_attempt_at`.\n- No unbounded queries; `LIMIT` and pagination will be considered for list operations.\n\n## 4. Concurrency & Resource Safety (Implicit)\n- All goroutines spawned (e.g., in worker pool) must have deterministic lifecycle and context cancellation (RULE-RES-02, TIER-2-RESIL §2.6). No `time.Sleep` in tests (RULE-TEST-003). All shared mutable state protected by mutexes or atomic operations (TIER-2-RESIL §2.6).
