# ImplSpec: Relaybox — Multi-Tenant Webhook Relay Service\n\n## Document ID: relaybox-trd\n\n### Core Principle: Contracts, Not Implementation\nThis ImplSpec defines **HOW** the system will be built, adhering strictly to Clean Architecture principles, specifying interfaces, structs, and method signatures without writing full business logic or method bodies.\n\n### 1. Database Schema Migration Plan\n**(ST-01: Database Schema Migrations)**\n- **Strategy**: Zero-Downtime Expand/Contract (if applicable for future changes, initial tables are direct create).\n- **Migration Tool**: `golang-migrate/migrate` (or similar).\n- **Scripts**:\n  - `migrations/001_create_events_table.up.sql`:\n    ```sql\n    CREATE TABLE events (\n        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),\n        tenant_id UUID NOT NULL,\n        event_type TEXT NOT NULL,\n        payload JSONB NOT NULL,\n        dedup_key TEXT NOT NULL,\n        created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),\n        created_by TEXT NOT NULL\n    );\n    CREATE UNIQUE INDEX idx_events_tenant_dedup ON events (tenant_id, dedup_key);\n    ```\n  - `migrations/001_create_events_table.down.sql`:\n    ```sql\n    DROP TABLE IF EXISTS events;\n    ```\n  - `migrations/002_create_subscriptions_table.up.sql`:\n    ```sql\n    CREATE TABLE subscriptions (\n        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),\n        tenant_id UUID NOT NULL,\n        event_type TEXT NOT NULL,\n        target_url TEXT NOT NULL,\n        created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),\n        created_by TEXT NOT NULL\n    );\n    CREATE UNIQUE INDEX idx_subscriptions_tenant_event_type ON subscriptions (tenant_id, event_type);\n    ```\n  - `migrations/002_create_subscriptions_table.down.sql`:\n    ```sql\n    DROP TABLE IF EXISTS subscriptions;\n    ```\n  - `migrations/003_create_outbox_table.up.sql`:\n    ```sql\n    CREATE TYPE outbox_status AS ENUM ('pending', 'processing', 'delivered', 'failed', 'dead_letter');\n    CREATE TABLE outbox (\n        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),\n        event_id UUID NOT NULL REFERENCES events(id) ON DELETE CASCADE,\n        subscription_id UUID NOT NULL REFERENCES subscriptions(id) ON DELETE CASCADE,\n        status outbox_status NOT NULL DEFAULT 'pending',\n        delivery_id UUID NOT NULL DEFAULT gen_random_uuid(),\n        attempts INT NOT NULL DEFAULT 0,\n        last_attempt_at TIMESTAMPTZ,\n        next_attempt_at TIMESTAMPTZ NOT NULL,\n        error_message TEXT,\n        created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),\n        updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),\n        UNIQUE (event_id, subscription_id)\n    );\n    CREATE INDEX idx_outbox_pending_delivery ON outbox (next_attempt_at) WHERE status = 'pending';\n    CREATE INDEX idx_outbox_event_sub ON outbox (event_id, subscription_id);\n    ```\n  - `migrations/003_create_outbox_table.down.sql`:\n    ```sql\n    DROP TABLE IF EXISTS outbox;\n    DROP TYPE IF EXISTS outbox_status;\n    ```\n\n### 2. Repository Implementations (Package: `pkg/repository`)\n**(ST-03: Postgres Event Repository Implementation)**\n**(ST-04: Postgres Subscription and Outbox Repositories Implementation)**\n- **`EventRepository`**: `PostgresEventRepository` implements `domain.EventRepository`.\n  - `SaveEvent`: Transactionally inserts event and associated outbox entries (FR-ING-02, RULE-DATA-01, RULE-EVT-02). Handles `dedup_key` for idempotency (FR-ING-03, RULE-DATA-02).\n- **`SubscriptionRepository`**: `PostgresSubscriptionRepository` implements `domain.SubscriptionRepository`.\n  - CRUD operations with `tenant_id` filtering (FR-SUB-02, RULE-SEC-01).\n- **`OutboxRepository`**: `PostgresOutboxRepository` implements `domain.OutboxRepository`.\n  - Methods for adding, fetching pending, updating status (delivered/failed/dead-letter).\n- **Dependencies**: `*sql.DB`, `domain.Clock`.\n\n#### 2.3. Service Implementations (Package: `pkg/service`)\n**(ST-05: Ingestion Service and HTTP Handler)**\n**(ST-06: Subscription Service and HTTP Handlers)**\n**(ST-07: Delivery Core Service and HTTP Client Infrastructure)**\n**(ST-08: Background Dispatcher Worker)**\n- **`IngestionService`**: `ingestionService` implements `domain.IngestionService`.\n  - Orchestrates `EventRepository` and `SubscriptionRepository` to create events and associated outbox entries.\n  - Responsible for generating `OutboxEntry` for each matching `Subscription` (based on `event_type`).\n  - **Dependencies**: `domain.EventRepository`, `domain.SubscriptionRepository`, `domain.OutboxRepository`, `domain.Clock`.\n- **`SubscriptionService`**: `subscriptionService` implements `domain.SubscriptionService`.\n  - Orchestrates `SubscriptionRepository` CRUD operations.\n  - Enforces `tenant_id` for all operations (FR-SUB-02, RULE-SEC-01).\n  - **Dependencies**: `domain.SubscriptionRepository`.\n- **`DeliveryService`**: `deliveryService` implements `domain.DeliveryService`.\n  - Orchestrates sending events to external webhooks.\n  - Uses `infrastructure.HTTPClient`.\n  - **Dependencies**: `infrastructure.HTTPClient`, `domain.OutboxRepository`.\n- **`Dispatcher` (Worker)**: `dispatcherWorker` for background processing.\n  - Periodically fetches pending `OutboxEntry` from `OutboxRepository`.\n  - Invokes `DeliveryService.SendEvent` for each entry.\n  - Implements retry logic with exponential backoff for transient failures, marks as dead-letter for permanent failures (FR-DEL-02).\n  - Uses `context.Context` for graceful shutdown and timeouts, bounded worker pool (FR-DEL-03, RULE-RES-02).\n  - **Dependencies**: `domain.EventRepository`, `domain.SubscriptionRepository`, `domain.OutboxRepository`, `domain.DeliveryService`, `domain.Clock`.\n\n#### 2.4. Transport / Handlers (Package: `pkg/handler`)\n**(ST-05: Ingestion Service and HTTP Handler)**\n**(ST-06: Subscription Service and HTTP Handlers)**\n**(ST-09: Health Endpoints and Base Observability Configuration)**\n- **`EventHandler`**: HTTP handler for `POST /v1/events`.\n  - Parses request body into DTO, resolves `TenantID` from `context.Context` (RULE-SEC-01).\n  - Calls `domain.IngestionService`.\n- **`SubscriptionHandler`**: HTTP handler for CRUD `POST/GET/DELETE /v1/subscriptions`.\n  - Parses request, resolves `TenantID` from `context.Context` (RULE-SEC-01).\n  - Calls `domain.SubscriptionService` methods.\n- **`HealthHandler`**: HTTP handler for `/livez` and `/readyz`.\n  - `/livez`: returns 200 OK.\n  - `/readyz`: checks DB connection status via a health check interface (FR-OBS-01, RULE-OBS-04).\n- **DTOs**: `pkg/handler/dto` for request/response payloads (`IngestEventRequest`, `SubscriptionRequest`, `SubscriptionResponse`).\n\n#### 2.5. Cross-Cutting Concerns / Main Setup (Package: `pkg/server`, `main.go`)\n**(ST-09: Health Endpoints and Base Observability Configuration)**\n- **Main `server.go`**: Sets up HTTP router (e.g., Gin/Echo), registers handlers.\n- **Middleware**: For structured logging (RULE-OBS-01), Prometheus metrics (RULE-OBS-03), and context propagation (RULE-RES-01).\n  - **`metrics.go`**: Middleware to capture request duration and status with bounded cardinality labels (`status=\"success|error\"`, `method=\"POST\"`).\n- **`config.go`**: Application configuration (e.g., database connection string, dispatcher settings).\n\n### 3. System Observability & Telemetry Blueprint (RULE-OBS)\n- **Structured Logging (`slog`)**: Configured globally. All logs will emit JSON, include `trace_id` and `span_id` automatically when `slog.InfoContext(ctx, ...)` is used (FR-OBS-02, RULE-OBS-01).\n- **Prometheus Metrics**: Defined and exposed via `/metrics` endpoint (FR-OBS-02, RULE-OBS-03).\n  - Counter: `relaybox_http_request_total{method=\"<METHOD>\", path=\"<PATH>\", status=\"<STATUS_CODE_GROUP>\"}`\n  - Histogram: `relaybox_http_request_duration_seconds{method=\"<METHOD>\", path=\"<PATH>\"}`\n  - Counter: `relaybox_delivery_attempt_total{status=\"delivered|failed|dead_letter\"}` (bounded cardinality, RULE-OBS-03).\n- **Distributed Tracing**: OpenTelemetry SDK initialized at startup. `infrastructure.HTTPClient` will automatically propagate trace context (FR-DEL-01, RULE-OBS-02).\n\n### 4.
